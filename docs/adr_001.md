# ADR-001: Use Django Modular Monolith Architecture

## Status
Accepted

## Context

The Campus Lost-and-Found System allows university students and staff to report lost and found items, search for matches, submit ownership claims, and manage item handovers.

The system must meet the following requirements:

- Support 200 concurrent users with 95% of item creation requests completed within 2 seconds.
- Continue operating when the notification service is unavailable for 15 minutes.
- Authenticate users through University SSO.
- Store application data within Kazakhstan.

## Decision

We propose using a **Modular Monolith Architecture** built with Django.

The backend will run as a single application, organized into independent Django apps:

- **accounts** — University SSO authentication.
- **items** — Lost and found item management.
- **matching** — Automated matching of reported items.
- **claims** — Ownership verification and handover management.
- **notifications** — Email and push notification handling.

PostgreSQL will store application data. Notification tasks will be persisted and processed asynchronously to prevent notification service failures from blocking core operations.

## Alternatives Considered

**Microservices Architecture**

Each feature could run as an independent service.

However, microservices would introduce additional deployment complexity, network communication overhead, and infrastructure maintenance.

## Positive Consequences

- Simpler development, testing, and deployment.
- Clear separation of responsibilities through Django apps.
- Easier maintenance and debugging.
- Reduced communication overhead between modules.
- Supports asynchronous notification processing.

## Negative Consequences

- Individual modules cannot be deployed or scaled independently.
- A failure in the main backend may affect several features.
- Strong module boundaries require team discipline.

## Conclusion

A Django Modular Monolith is a suitable initial architecture because it balances maintainability, performance, and development simplicity for the Campus Lost-and-Found System.
